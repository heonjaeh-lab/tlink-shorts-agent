# 티링크 설치 사례 숏츠

입력은 현장 담당자가 쓰는 말로 받는다. “어디에 무엇을 설치해 어떤 일을 할 수 있게 됐는지”와 첨부 소재를 사례 하나로 묶는다. 생성·실행을 요청받으면 실제 MP4까지 확인한다. 프롬프트나 지침만 요청받으면 해당 단계의 산출물을 전달한다.

## 현장 메모를 장면으로 옮기기

1. 공개 가능한 현장명, 출발·도착 지점, 설치 장비·기능, 실제 사진, 성과 근거를 추린다. [설치 사례 목록](references/설치사례_목록.md)과 [기술·장비 자료](references/티링크_기술과_장비.md)로 확인한다. 한 고객의 장비·도시·성과를 다른 고객의 이야기로 가져오지 않는다. 실제 설치·효과를 말하는 편은 [실제 사례 사실 기록](references/제작_인계.md)에 같은 사례 ID로 연결한다. 근거표의 제품·도착지·사용 기능·성과 문장을 실제 자막과 대조한다. 가상 활용편은 첫 화면에 그렇게 표시한다.
2. 대표의 얼굴·가르마·안경·남색 재킷, 원본 선화·셀 음영·구도는 유지한다. 바뀌는 요소는 업종별 **상담실, 달리는 거리, 도착 출입구·간판**, **장비의 실제 외형과 잡는 법**, **그 사례의 경로**다. 지리적 좌표는 지도 컷에서 사용하고 건물 외관은 현장 사진이나 사례용 미술 지시에서 가져온다. [힉스필드 장면 입력과 공장 교체 예시](references/힉스필드_장면입력.md)
3. 첫 15초에 구체적인 고객 질문과 제품 화면을 함께 넣는다. “어느 화면에서 무엇을 보고 다음 응대를 어떻게 바꾸는지”가 보여야 한다. 한글 자막과 사실에 쓰이는 제품 UI는 원본을 편집한다. 화면은 버튼·레이블 등 공개할 영역만 잘라 쓰고 그 위에 올리는 상담 예시는 구분한다. [영어학원 기능 12개와 대본](references/영어학원_숏츠_제작지침.md)
4. 달리기와 출입구에는 동일한 주 장비를 등장시킨다. 몸에 받치는 손, 앞면 방향, 크기, 자유로운 손으로 문을 여는 동작을 확인한다. 지도에는 장비 없이 대표 얼굴 배지만 띄운다. 새 위치에 대한 입력은 확인된 양쪽 주소 또는 좌표다. 지도 조회·사용 범위·영상 출력은 [네이버 지도 연동](references/네이버_지도_연동.md)에 따른다.
5. 끝에서는 가능하면 같은 현장의 실제 설치 사진을 먼저 보여주고, 해당 현장에서 확인된 이용 기능이나 결과를 얹는다. 사진과 실제 결과가 없는 가상 활용편은 애니메이션 엔딩과 적용 예시를 쓴다. 영어학원은 학원 등록 기록에서 상담 후 일정 기간 내 등록한 고유 신규 문의자 비율을 같은 기준으로 비교한다. 실제 전후 자료가 오기 전에는 수치나 개선 방향을 만들지 않는다. 병원은 예약 변경의 요청·확인·확정 상태를 유지한다. 업체 자체 보고서의 숫자는 [경영분석 자료](references/경영분석_보고서_검토.md)에서 맥락을 확인한다.

## 실행

이 스킬 폴더의 스크립트를 사용한다. 작업물은 사례별 실행 폴더에 쓴다. 패키지에 포함된 영어학원 실행 사례는 `영어학원_숏츠_실행/사례.json`이다. 사용자가 JSON을 만들 필요는 없다. 에이전트가 메모·사진·대사를 정리한다.

1. **준비.** 사례 JSON의 입력 형식은 [강일학원](examples/강일학원_편집사례.json)과 [공장](examples/공장_장소장비_교체예시.json)을 참고한다. `python3 scripts/run_short.py CASE.json --prepare --out-dir RUN`으로 사례별 `생성_브리프.json`을 만든다. 경로는 원칙적으로 사례 JSON 기준이다. 실제 사례에는 같은 ID의 `fact_case`를 연결한다.
2. **힉스필드 생성.** 원본을 읽고, 대표 얼굴과 화풍 참조 프레임을 추출한다. 새 장비에는 해당 제품 참조를, 새 건물에는 허용된 외관 참조를 연결한다. 힉스필드 **플러그인**에서 현재 모델의 참조 역할, 비용, 작업 공간을 확인한다. 사용자의 예산·생성 의사를 존중한다. 레퍼런스 업로드·확인 후 브리프의 `shots.qa`, `shots.run`, `shots.arrival` 중 필요한 컷만 제출한다. 예시의 Q&A는 8초 무음 상담실 투샷이며, 첫 15초의 나머지는 기능 화면으로 이어진다. 결과 작업 ID와 생성 인자를 기록하고 같은 ID로 완료·파일을 확인한다. 이미 확보한 완성 컷은 재생성하지 않는다.
3. **지도와 이동.** 원본과 동일한 사례에서 채택한 이동 영상은 정상 속도와 간판을 살린다. 신규 사례는 NAVER 지도 결과를 별도 배경으로 고정하고 그 위에 경로·얼굴 배지를 합성한다. `run_short.py`가 새 지도와 달리기·입장을 조립한다. 움직이는 간판에 새 글자를 고정 좌표로 붙이면 어긋나므로, 기본 도착 컷은 정면 고정 카메라로 만든다. 공개명은 `site.sign_mode=overlay`, `site.sign_text`, `site.sign_box=[좌,상,우,하]`(0–1)로 정확히 합성한다.
4. **최종 편집.** 사례 JSON의 `media_files`에 `qa`, 필요에 따라 `run`, `arrival`, `badge`를 연결한다. 같은 사례용으로 이미 만든 지도가 있으면 `map`을 연결할 수 있다. `editing.opening`은 `qa_beats` 순서로 역할·배치·공개 UI 사각형을 지정한다. `editing.closing`에는 엔딩 문구를, `editing.site_photo`에는 동일 현장 사진의 경로와 사용 범위를 넣는다. 마지막 컷 길이는 전체 목표 시간에 맞춰 정해진다. 설치 사진 위에 설명을 띄울 때는 `layout: photo_result`와 `caption_delay_s`를 쓴다. 영어학원 편은 25–26.5초에 `photo_result`의 `lines`를 생략해 사진·제목·출처 관계만 표시한다. 26.5–30초에는 `layout: feature_focus`로 전환해 8초 구간처럼 제품 화면을 크게 보여준다. 이 컷의 `feature.file`에 공식 성공통화 이력 이미지를, `feature.detail_crops`에 기간 선택과 재생 버튼의 두 영역을 지정한다. 아래에 상담 전후의 발화 예시를 표시한다. 별도 설치처 참고 사진을 사용하는 예시 편은 `site_photo.relation: reference_case`, `same_site: false`, 사진의 성격을 알리는 `label`(예: 설치 참고 사진)을 지정하고, 마지막 설명에도 활용 예시임을 표시한다.
5. **렌더.** `python3 scripts/run_short.py CASE.json --out-dir RUN`을 실행한다. 필요에 따라 `--qa`, `--run`, `--arrival`, `--map`, `--badge`로 파일을 지정한다. 실제 경로·장비가 필요한 신규 사례는 원본의 강일학원 지도·소품으로 대체하지 않는다. 결과는 `RUN/숏츠.mp4`이다. 로컬 편집은 Python 3.11 이상, Pillow, FFmpeg, FFprobe와 한글 글꼴을 사용한다.
6. **검수.** FFprobe로 길이·세로 비율·프레임·오디오를 확인한다. 문답의 화자 교대, 기능명과 버튼, 지도 전환, 문 닫히기 직전의 장비, 마지막 사진·자막을 실제 프레임으로 확인한다. 게시용 성과와 가상 예시를 구분해 결과물과 남은 현장 자료를 인계한다.

기존 프로젝트에서 이미 10초씩 세 구간으로 만든 manifest는 [기존 편집 입력 계약](references/제작_인계.md)의 `compile_case.py`·`render_preview.py` 방식으로 계속 편집할 수 있다.
