## 확인된 강점과 해자 가설

- **공식 자료에서 확인한 것.** 티링크는 기존 전화 환경에 맞춰 녹취를 붙이는 구성, 녹취·이력·AI 요약의 연결, 모바일·PC폰·CRM 연동, 현장별 하드웨어 배치와 커스터마이징을 공개한다. 녹취 파일의 AES-256 암호화와 비밀번호의 SHA-256 단방향 해시도 제품 문서에 기재돼 있다. 적용 제품·현장의 설정 및 제3자 보안 검증 범위는 별도로 확인한다. [AI 녹취 기술](https://www.tlinkcrm.com/recording.php) · [설치 형태](https://www.tlinkcrm.com/case.php) · [회사 역량](https://www.tlinkcrm.com/)
- **회사가 공개한 개발·실적 이력.** 회사는 자체 녹취 엔진 개발을 소개하고, 연혁에 ARM CPU 기반 녹취 서버·AI 스마트 콜센터·다국적 작업자 통역 관련 특허 등록과 한국전력 고객센터 3,000석, IVY 김영학원 고객센터 700석 녹취 서버 공급을 기재한다. 다국어 작업지시 건은 특허청 제공 공개 메타데이터에서 출원번호 10-2025-0163102와 SIP 기반 단말 구성이 확인되며, 그 자료만으로 등록번호·유효 상태·권리범위를 확정할 수 없다. 도입 실적은 공개된 설치·공급 범위에 한해 쓴다. [티링크 연혁](https://www.tlinkcrm.com/history.php) · [특허청 제공 서지·초록](https://k-knowledge.kr/srch/read.jsp?id=292395775)
- **에이전트가 사용할 차별화 가설.** 기존 장비와 업무 흐름에 맞춰 통신과 상담 이력을 연결하고, 현장별 제약에 맞게 장비 배치까지 구현하는 역량이 도입 마찰을 낮출 수 있다. 티링크온은 무전, 기록, 통역을 한 흐름에 연결하는 점을 활용 가설로 삼는다. 경쟁사 대비 우위·전환 비용·시장 지배력·고객 성과는 별도 검증 항목이다. [AI 녹취 구성](https://www.tlinkcrm.com/recording.php) · [티링크온 기능](https://www.tlinkcrm.com/tlinkon.php)

## 1차 시나리오의 사실 경계

| 시나리오 | 우선 기능 | 마지막 10초에서 말할 수 있는 범위 |
| --- | --- | --- |
| **병원 · 예약 변경 문의 인계** | `REC-01`로 이전 문의를 조회하고, 활성화 근거가 있을 때 `REC-02` 또는 `CRM-01`로 핵심과 메모를 확인한다. `SMS-01`은 문자 연동과 담당자 발송 기록이 확인된 경우 사용한다. | 상태는 **변경 요청 접수 → 담당자 확인 → 변경 확정** 중 입력과 일치시킨다. “다음 근무자가 지난 문의를 확인할 수 있습니다”는 기능 활용 설명이다. 실제 인계 개선이나 변경 완료는 운영 자료가 있을 때만 과거형으로 서술한다. 환자 이름·연락처·진료정보·실제 통화 원본은 가상 데이터 또는 승인된 가림 소재로 대체한다. |
| **영어학원 · 입학 상담 인계** | `REC-02`로 레벨테스트·시간표 등 상담 요점을 확인하고, 필요하면 `REC-01`로 통화를 다시 찾는다. | “다음 담당자가 이전 안내를 확인하는 활용 예시”는 가능하다. 녹취 서버 공급 사실만으로 해당 학원에 AI 요약을 활성화했다고 쓸 수 없다. 학생과 학부모 정보는 가상 자료를 사용한다. |
| **다국적 공장 · 작업 전달** | `PTT-01` 그룹 무전과, 실제 옵션이 확인된 경우 `PTT-02` 통역을 연결한다. | 단말 전달 및 지원 언어 설정 후 작업 요청을 주고받는 장면을 보여준다. 실제 사업장이 사용한 제품·언어·효과는 현장 자료에서 확인한다. 앱형만 도입했다면 기존 스마트폰 설정으로 표현한다. |

실제 사례의 `도입 후 결과`는 출처에 있는 관찰·인수 확인 또는 측정 자료로 방어할 수 있는 문장만 쓰고, 측정 수치는 비교 기간·분모·기준을 기록한다. 제공된 결과가 없으면 마지막 카피를 `이 기능으로 할 수 있는 업무`로 작성한다. 공식 상품 사진은 상품 형태 참고에, 현장 사진은 실제 장소의 설치 사실 증빙에 쓴다.
