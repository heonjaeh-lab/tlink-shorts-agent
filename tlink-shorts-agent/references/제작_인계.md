# 티링크 숏츠 제작 인계

이 문서는 설치 사실 기록과 초창기 10초씩 세 구간을 쓰는 편집 계약을 설명한다. 현재의 15초 Q&A, 힉스필드 컷, 사례별 지도는 [스킬 실행 절차](../SKILL.md)를 따른다. 실제 사례의 `fact_case`는 이 문서의 현장 근거 형식을 사용한다.

## 팀의 역할과 결과물

| 담당 | 입력과 출력 |
| --- | --- |
| 영업·설치 담당 | 고객 문제, 설치 도시·장비·위치, 실제 사용 기능, 확인 가능한 업무 변화, 사용 승인된 설치 사진을 제공한다. 특별한 양식 없이 메모와 파일로 제출할 수 있다. |
| 에이전트 | 같은 설치 사례의 근거를 대조해 `case.json`으로 정리하고, `manifest.json`과 `review.md`를 만든다. 사진 근거와 기능 근거를 구분한다. |
| 영상 팀원 | 승인 프롬프트 또는 연출 자료를 전달한다. 에이전트는 도시·장비·캐릭터·길이 등의 구조화된 변수와 이미 완성된 파일을 받아 활용한다. |
| 편집·검수 | 30초 타임라인을 조립하고 재생해 최종 초안을 확인한다. 실제 현장 사진과 10초 이동 영상의 관계가 명확해야 한다. |

## 에이전트 정리용 JSON

기본 형태는 [병원 예시](../examples/병원_활용예시.json)를 복제한다. 파일 경로는 `case.json`이 있는 폴더 기준 상대 경로 또는 로컬 절대 경로다.

| 키 | 입력 기준 |
| --- | --- |
| `case_id`, `scenario`, `mode` | 실행용 사례 ID. 유형은 `hospital`, `academy`, `factory`, `other`. 사실 모드는 `real`, `example`, `pre_install`. |
| `site_name` | 해당 영상에 사용할 승인된 현장명 또는 익명 표기. |
| `destination.name`, `equipment.name`, `equipment.placement` | 도시와 주 장비의 이름·위치 또는 단말 설정. 실제 사례에서는 각각 해당 사례 근거 ID를 연결한다. |
| `character.kind`, `character.approved` | `representative`는 대표자 이미지·캐릭터 사용이 확인돼야 한다. 내부 예시에는 `stand_in`을 쓸 수 있다. 캐릭터 원본은 외부 AI 전송 범위까지 별도 확인한다. |
| `features` | `[{"id":"REC-01","evidence":["E03"]}]`처럼 기능 코드와 근거 ID를 적는다. 상세 조건은 기술·장비 참고자료에 있다. |
| `photo` | `path`, `relation`(`same_case`, `reference_case`, `missing`), `approved`(현재 목적에 사용할 수 있음), `evidence`. 실제 사례는 `same_case`와 근거가 필요하다. |
| `result` | `kind`는 `observed`(실제 운영 변화) 또는 `use_example`(사용 방식). 관찰 결과의 근거는 `evidence`에 연결한다. |
| `reservation_state` | 병원만 필수. `request`, `review`, `confirmed` 중 해당 상태를 유지한다. |
| `evidence` | ID를 키로 하고 각 값은 `{"case_id":"...","type":"...","source":"문서와 해당 위치 또는 현장 담당자 확인 기록"}`. 유형은 `location`, `installation`, `feature_used`, `site_photo`, `observed_outcome`. |
| `copy` | `question`, `answer`, `ending`, `cta`. 화면 문구는 한국어로 만들고, 실제 기사나 인터뷰에서 유래하지 않은 대사는 예시 또는 재구성으로 표시한다. |
| `media` | `qa`(선택, 배경 사진·영상), `travel`(필수, 승인된 10초 영상), `travel_approved`(도시·지도·인물·장비 검수 완료), `voiceover`(선택, 30초 안에 들어오는 음성 믹스). |

`review.md`에는 용도, 문장별 근거 ID와 출처, 공개명·사진·캐릭터 사용 범위, 예약 상태, 사진 가림 내역, 누락 항목을 적는다. 컴파일러는 근거의 종류와 동일 사례 연결, 로컬 소재를 검사한다. 서술을 뒷받침하는지와 사진·영상 내용이 자료와 일치하는지는 에이전트와 담당자가 확인한다.

## 영상 팀원에게 넘길 변수

- `duration_s: 10`, `aspect: 9:16`, `origin: 서울`, `destination: 확인된 설치 도시`, `equipment_name`, `equipment_reference`, `character_reference`, `map_reference`
- 승인된 **한반도 지도**에서 실제 도시 위치에 핀을 넣고, 확인된 두 도시 이름은 편집 레이어에서 작성한다. 대표자 캐릭터는 들고 있는 하나의 주 장비와 함께 이어지는 모습을 보여준다. 출발과 도착은 설치 계획의 시각적 연출이다.
- 팀원이 주는 영상 프롬프트·지역 핀·이미지 참조를 연결한다. 납품 전 9:16, 최소 10초 재생 가능, 글자 가림 없음, 도시 위치와 장비 일치 여부를 확인한다. 사진은 편집용으로 남긴다.

## 판정과 파일

| 상태 | 다시 실행할 때 채울 내용 |
| --- | --- |
| `needs_case_details` | 도시·장비·효과 근거·사진 사용 범위 등 `requests`를 확인한다. 계획과 문답은 공유할 수 있다. 실제 사례의 최종 영상은 필요한 자료 확인 후 진행한다. |
| `needs_generated_media` | 지도 클립 생성·확인 또는 선택 파일 경로를 점검한다. 파일이 존재해도 도시·장비가 틀리면 교체한다. |
| `ready_for_edit` | `manifest.json`을 로컬 렌더러 또는 CapCut 타임라인에 전달한다. |

매 실행마다 새 출력 폴더 또는 새 파일명을 쓴다. 로컬 렌더러는 Python 3, Pillow, FFmpeg, FFprobe, 한글 글꼴이 필요하다. Mac 기본 글꼴을 찾지 못하면 `--font`로 한글 글꼴 파일을 지정한다. 기본 구성은 1080×1920, 30fps, 30초이며 원본 영상의 음성은 제외된다. 30초 내레이션 파일을 주면 음성 트랙으로 넣는다.

CapCut을 쓰는 경우 0–10초 문답 배경 및 자막, 10–20초 지도 영상, 20–30초 실사 사진을 각 시간에 배치한다. `get_timeline`으로 종료점과 자막을 확인하고 편집 초안을 저장한 뒤 Desktop에서 내보낸다.
