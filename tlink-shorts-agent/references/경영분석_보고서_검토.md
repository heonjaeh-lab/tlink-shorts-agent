# 티링크 상담분석 보고서 검토

공개 보고서의 **2026년 8월 3~9일** 데이터와 네 개 탭을 검토했다. 기준일은 8월 10일이며 비교 기간 자료는 없다. 티링크가 상담 대화를 어떤 운영 자료로 바꿀 수 있는지 보여주는 근거로 사용한다. 개별 고객 도입의 사용 현황이나 성과는 각 현장의 자료로 확인한다. [티링크 콜센터 상담분석 보고서](https://www.tlinkcrm.com/management.php)

## 1. 경영 분석 대시보드

| 항목 | 보고서에서 확인한 내용 | 영상에 적용할 방식 |
| --- | --- | --- |
| 표본 | 총 115건은 STT 통화 기록 108건과 CRM 메모 7건의 합이다. 내용을 확인해 평가할 수 있는 것은 STT 중 60건(55.6%)이다. 평균 통화시간 93.4초의 기준은 STT 108건이다. | 서로 다른 분모를 합쳐 효과 수치로 사용하지 않는다. 내용 확인 여부를 먼저 점검하는 기능으로 소개할 수 있다. |
| 영업기회 | 보고서는 우선순위가 부여된 영업기회 6건(P1 2, P2 3, P3 1)을 제시한다. 상태에는 견적발송, 접수완료, 검토중, 통화필요, 설치예정이 섞여 있다. 영업 성격 상담이 담당자별 5건 미만이어서 전환율을 계산하지 않았다. | ‘견적 발송’은 견적 발송으로, ‘설치 예정’은 예정으로 쓴다. 신규 매출을 표현하려면 계약, 매출 인식 또는 해당 수치의 기준을 따로 확인한다. |
| 후속조치 | CRM 메모 7건 중 결과 미기재 6건과 처리중 1건을 분리했다. 7일 이상 경과 4건을 표시했다. 결과 필드가 없는 STT는 이 집계 범위에서 빠진다. | 영상에는 ‘미기재 상담을 찾아 확인할 수 있어요’처럼 기록 점검으로 표현한다. 실제 미처리나 고객 이탈로 해석하려면 별도 근거가 필요하다. |
| 경보·VOC | 통화 파일 업로드 오류가 상담 3건에 반복되어 긴급 경보 1건이 표시됐다. 경보 규칙은 동일 이슈 반복이다. VOC는 유효 항목 9가지로, 업로드 오류·착신·로그인·원격지원·전화 연결/음질·헤드셋·녹취서버 확인·발신 장애·무음이 포함됐다. 상담 건수와 발화 언급량을 따로 집계한다. | ‘반복 이슈를 묶어 우선 확인한다’는 화면을 만들 수 있다. 원인 확정, 장애 해결, 개선율을 말하려면 처리 결과를 확인한다. |
| 이탈·추이 | 이번 데이터에서 명확한 기존 고객 이탈 표현은 확인되지 않았다. 과거 해지 정책 설명, 개통 전 사전 취소, 신규 수주 실패는 사례가 달라 따로 처리했다. 이전 비교기간이 없고 일부 일별 추이를 확인할 수 없었다. | 키워드만으로 이탈을 확정하지 않는다. 전후 수치 비교에는 기간·분모·집계 기준이 모두 필요하다. |

보고서에는 일별 상담량, 인입·발신 구분, 담당자별 상담량, VOC 시각화도 있다. 귀속이 불명확한 짧은 소프트폰 내선 26건은 전체 콜량에만 반영돼 개인 평가 근거로 사용되지 않았다. [경영 분석 대시보드](https://www.tlinkcrm.com/management.php)

## 2. 상담원 역량 분석

내용을 볼 수 있는 상담을 바탕으로 응대 유형, 요구 파악, 상품 설명, 공감, 문제 해결과 후속 안내를 분석한다. 평가 가능 표본은 각각 32건, 24건, 4건이다. 세 번째 표본은 기준인 5건 미만이라 평가를 보류했다. 대기시간·타임스탬프가 없어 응대속도는 모두 확인 불가로 표시했다. 팀 개선안에는 반복 문의 답변 표준화, 네트워크 상태 선확인, 장애 후속 연락 시점 안내가 포함됐다. 홍보 영상에는 개인 점수·이름·상담 원문을 옮기지 않고, 가상 사례의 업무 개선 방식만 설명한다. [상담원 역량 분석](https://www.tlinkcrm.com/management.php)

## 3. 인사고과 평가표

고객 요구 파악(20%), 설명·상품 이해(20%), 공감·친절(15%), 문제 해결(20%), 클로징·후속조치(15%), 스크립트·컴플라이언스(10%)의 권장 가중치를 예시로 썼다. 신뢰도는 유효 상담 20건 이상 높음, 10~19건 중간, 5~9건 낮음, 5건 미만 평가 보류다. 스킬은 이를 **분석 결과 예시**로 참조하고 기업의 확정 인사 정책이나 해당 직원의 공식 성과로 사용하지 않는다. [인사고과 평가표](https://www.tlinkcrm.com/management.php)

## 4. 신입사원 교육자료

상담에서 확인한 응대를 모범·개선 사례로 나눈 뒤 안내 스크립트와 체크리스트로 바꿨다. 다룬 유형은 신규 문의의 비용과 조건 안내, 원격지원 앱 오류 대응, 전화 연결 문제 분리 진단, 청구·납부 문의다. 교육용 롤플레잉은 신규 고객, 원격지원 오류, 납부 방식 변경 세 사례를 대화로 재구성했다. 이는 **기록 → 반복 패턴 → 직원이 실제로 쓸 교육자료**라는 기능 설명에 활용할 수 있다. 도입 성과를 표시하려면 자료 사용 후의 업무 변화가 별도로 확인되어야 한다. [신입사원 교육자료](https://www.tlinkcrm.com/management.php)

## 병원 숏츠에 적용하는 판정

- 보고서의 병원 문의 사례는 **녹취 도입 문의와 견적 안내 단계**까지 확인된다. 다른 병원의 현장 사진을 이어 붙여 해당 문의가 실제 설치와 성과로 이어졌다고 표현하지 않는다.
- 팀의 병원 가상 시나리오는 **예약 변경 문의 → 통화 기록 확인 → 다음 근무자 인계**를 보여준다. 화면 예시는 `변경 요청 접수`와 `변경 확정`을 구별한다. 환자 정보와 원본 통화가 없는 가상 데이터 또는 승인된 비식별 사본을 사용한다.
- 문자 발송이나 CRM 기록 연결은 해당 상품·옵션, 실제 사용 여부를 확인한 경우에만 실제 사례 문구에 추가한다. 이 보고서는 대화 분석의 근거로 쓰고 시스템이 예약을 대신 변경했다고 설명하지 않는다.
- 자료가 있으면 `어떤 기능을 사용했나 → 어떤 절차가 달라졌나 → 무엇으로 확인했나` 순서로 영상 결말을 쓴다. 성과 자료를 받지 못하면 `기능 사용 예시`를 쓴다. 고객사 도입 전후 효과나 개선률은 보고서의 상담 집계와 연결하지 않는다.
