# 티링크 설치 사례 30초 스토리라인

모든 업종에 영어학원 최종본의 장면 순서와 시간표를 적용한다. 대표 캐릭터와 각 컷의 역할은 공통이다. 업종별로 고객의 말과 업무 행동, 추천 기능과 그 화면, 실제로 취급한 장비, 장소와 사진을 채운다. 먼저 **“마지막에 현장 담당자가 어느 화면에서 무엇을 확인하면 첫 질문에 답할 수 있는가?”**를 한 문장으로 정하고 문답을 작성한다.

## 공통 시간표

| 시간 | 장면 | 콘티에 적을 내용 |
| --- | --- | --- |
| 0–3초 | 고객의 고민 | 첫 프레임부터 고객이 한 문장으로 묻는다. “누가 어떤 일을 하다가 무엇을 놓치는지” 또는 “무엇을 알기 어려운지”가 드러나게 쓴다. |
| 3–15초 | 대표의 답변과 실제 기능 시연 | 대표가 기능을 추천하는 말에 맞춰 **실제 티링크 화면**을 띄운다. 담당자가 누르는 메뉴·버튼과 그 결과를 보여준다. 예를 들어 ‘통화 요약을 연다 → 어떤 문의였는지 읽는다 → 원본을 재생해 빠진 안내를 확인한다’처럼 시청자가 따라갈 수 있는 순서로 쓴다. |
| 15–약 21.7초 | 대표가 장비를 들고 현장으로 이동 | 대표가 해당 장비를 들고 출발한다. 지도에서는 얼굴 배지만 출발지에서 도착지로 움직이고, 입구에서는 대표가 같은 장비를 들고 안으로 들어간다. 출발·도착 지점, 현장 외관·간판, 장비 참조 사진을 사례 자료에서 가져온다. |
| 약 21.7–25초 | 달라질 업무 행동 한 가지 | 고객이나 직원이 다음번에 어떻게 행동할지 짧은 대사 또는 동작으로 보여준다. 마지막 화면에서 확인할 수 있는 행동을 고른다. |
| 25–26.5초 | 실제 설치 사진 | 장소 제목과 작은 사진 표기를 붙이고 장비가 보이게 둔다. 동일 현장은 ‘실제 설치 사진’, 별도 현장 자료는 ‘설치 참고 사진’으로 표시한다. |
| 26.5–30초 | 개선 여부를 확인하는 실제 기능 화면 | 사진에서 제품 화면으로 전환한다. 담당자가 확인할 버튼·기록을 확대하고, **어떤 기록을 보거나 어떤 동작을 해 보면 앞의 행동이 달라졌는지 알 수 있는지** 한 문장으로 마무리한다. 응대 전후를 연출하면 ‘응대 예시’로 표시한다. 이 화면을 마지막 프레임까지 유지한다. |

약 21.7초는 영어학원 원본의 입장 완료 시점이다. 다른 현장 클립에서는 15–25초 안에서 이동과 업무 행동 사이의 컷 지점을 조정한다. 첫 15초의 문답·시연과 마지막 ‘사진 → 기능 확인’ 순서는 세 업종 모두 같다.

## 업종별 작성 예시

아래 대사와 업무 변화는 **활용 예시**다. 실제 설치 편에는 그 현장에서 확인한 기능·장비·장소를 넣는다.

| 업종 | 고객 고민 → 첫 15초 실제 화면 | 이동 장비·장소 | 바뀌는 행동 → 마지막 실제 화면에서 확인할 점 |
| --- | --- | --- | --- |
| 영어학원 | 원장 “상담은 많은데, 왜 등록이 안 될까요?” → 통화 요약을 열고 고객·상담원 키워드를 비교한 뒤 원본을 재생해, 테스트 날짜 문의에 어떤 답을 했는지 듣는다. | 대표가 학원 편의 납작한 녹취 서버를 들고 이동해 학원으로 들어간다. | “토요일 10시 어떠세요?”처럼 시간을 제안한다. → 원장이 **상담이력 → 성공통화 이력**에서 기간을 선택하고 다음 상담을 재생해 시간 제안이 있었는지 듣는다. 실제 등록률은 학원의 전후 기간·인원·집계 기준이 확인된 경우에 쓴다. |
| 병원 | 접수 직원 “교대하면 환자분이 몇 시로 바꿔 달라고 했는지 다시 물어봐요.” → 상담이력에서 이전 통화를 조회·재생해 요청 시간을 찾는다. 전사·요약을 사용 중인 현장은 실제 요약 화면도 연결할 수 있다. | 대표가 현장에서 확인된 녹취 장비를 들고 병원으로 들어간다. 접수 데스크와 장비 설치 공간은 현장 자료에 맞춘다. | 다음 근무자가 “오후 3시로 변경을 요청하셨군요”라고 이어받는다. → 다음 근무자가 **같은 문의의 상담이력**을 열고 녹취에서 요청 시간을 찾아낼 수 있는지 보여준다. 변경 확정은 병원 예약 기록으로 확인된 경우에만 표시한다. |
| 다국적 직원이 있는 공장 | 현장 반장 “포장 상자가 바뀌면 다른 언어를 쓰는 조에도 어떻게 전달하죠?” → 실제 **티링크온 그룹 무전** 화면에서 포장조를 선택해 요청한다. 통역 옵션과 사용 언어가 확인되면 양쪽 단말의 통역 시연을 연결한다. | 대표가 해당 현장의 무전 단말을 들고 공장 출입구로 들어간다. 앱형 현장은 사용 중인 업무용 스마트폰으로 설정 동작을 보여준다. | 작업자가 “파란 상자로 바꾸겠습니다”라고 지시를 되짚는다. → **같은 작업 그룹의 무전 화면**에서 요청과 회신을 시연해 내용이 맞게 전달됐는지 확인한다. 무음 영상은 실제 시연 발화를 자막으로 옮긴다. |

## 입력과 사실 확인

- 사례 ID, 업종·시청자, 고객의 업무 메모, 설치 위치·도시, 장비와 대표 캐릭터의 참조 자료, 현장 사진을 받는다. 회선·연동·선택 옵션과 기존 장비·신규 공급 장비를 구분한다. 실제 도입 편의 추천 기능은 해당 현장의 사용 기록과 대조한다.
- 첫 시연과 마지막 확인에 각각 실제 제품 캡처·화면 녹화 또는 실제 단말 시연을 연결한다. 같은 화면도 처음에는 문제를 찾는 데, 마지막에는 다음 건에서 달라진 행동을 확인하는 데 쓸 수 있다. 제품 화면이 없으면 필요한 메뉴·버튼·동작을 촬영 요청으로 명시하고 나머지 콘티를 작성한다.
- 실제 제품 화면의 데이터와 편집용 가상 대사를 구분한다. 개인 식별 정보는 가리고 실제 사진·인물·음성의 사용 범위를 기록한다. 가상 문답은 시작부터 ‘활용 예시’ 또는 ‘상담 상황 재구성’으로, 대표자의 방문·이동은 설치 연출로 표시한다.
- 마지막 장면에서는 화면으로 관찰할 수 있는 사실을 말한다. 실제 등록률 변화, 예약 확정, 생산성 개선처럼 별도 기록이 필요한 결과에는 해당 현장의 근거를 연결한다. 실적 자료가 없으면 담당자가 개선 여부를 확인하는 방법을 보여준다.

## 편집에 넘길 결과

- `storyboard.json`에 `case_id`, `case_mode`(`confirmed` / `application_example`), `status`, `issue`, `feature`, `hardware`, `photo`, `shots`, `requests`를 기록한다. `hardware`에는 장비명·기존/신규 구분·위치·적용 조건·참조 에셋을, `photo`에는 `asset_id`, `relation`(`same_case` / `reference_case` / `missing`), `label`, `approval_ref`를 적는다.
- `shots`는 공통 시간표 순서로 작성한다. 컷마다 `id`, `role`, `start_ms`, `end_ms`, `source_type`(`graphic` / `generated_clip` / `test_capture` / `real_photo`), `asset_id`, `voiceover`, `overlay`, `labels`, `evidence_ids`를 적는다. 공식 캡처와 실제 제품 시연은 `test_capture`로 연결하고, 생성 컷에는 `motion_prompt_en`과 `reference_ids`를 추가한다.
- `review.md`에는 기능·장비·장소·사진의 근거와 공개 범위, 마지막 화면에서 담당자가 판단할 기준을 기록한다. 자료가 갖춰지면 `ready_for_generation`, 누락되면 `needs_input`과 필요한 자료를 적는다. 예를 들어 “포장조의 요청과 회신이 담긴 티링크온 단말 시연”처럼 요청한다.
- [편집 스킬](../installation-shorts-editing/SKILL.md)에 넘길 때 이 콘티의 장면별 시간을 명시한다. 첫 기능 시연은 15초까지, 사진은 25초부터, 마지막 기능 화면은 26.5초부터 30초까지로 지정해 편집 단계에서도 같은 흐름을 유지한다.
